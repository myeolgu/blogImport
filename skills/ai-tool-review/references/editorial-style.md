# ToolScout Editorial Style

## Voice

- Write in clear, concise English for global creators.
- Sound like a practical editor who has tested the workflow, not a salesperson.
- Be specific, calm, and useful. Prefer evidence over excitement.
- Use second person when giving advice: “Use it when…” and “Choose this if…”.
- Avoid hype words such as “革命적”, “game-changing”, “必須”, “perfect”, and “best” unless a comparison explicitly supports the claim.

## Fixed review structure

1. **One-line verdict** — State who should use the tool and why.
2. **What it does** — Explain the core workflow in 2–3 sentences.
3. **Best for** — Name a concrete creator type or job.
4. **Pricing** — State the free plan and paid entry price only when verified; include the source date internally.
5. **Pros** — Three short, specific points.
6. **Cons** — Two short, specific points.
7. **Limitations** — Explain the main reason not to choose it.
8. **Visit the tool** — Use a clear CTA and preserve the affiliate disclosure.

## Sentence rules

- Keep paragraphs to 1–3 sentences.
- Use one idea per sentence.
- Use title case only for proper names; use sentence case for headings.
- Do not repeat the tagline in the description.
- Never invent a benchmark, user count, review score, feature, or price.
- If information is uncertain, say “Check the current plan page” instead of guessing.

## Consistency checklist

- Match `category`, `tagline`, `description`, `bestFor`, `price`, `pros`, and `cons` in `app/tools.ts`.
- Keep the same rating scale across tools.
- Use the same CTA wording pattern: `Visit {Tool name}`.
- Keep the disclosure visible on every monetized review page.
